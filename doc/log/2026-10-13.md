## Project started #setup

Owner's goal: get the OpticFilm 120 working again by any means, preferably on Linux with a user-space driver (kernel driver acceptable if needed). The unit fails with vendor software on both Windows and macOS. Cause unknown.

## Sensitive data stays out of git #privacy

Serial numbers, the registration email and the scans that show them are kept in `work/sensitive.md` (untracked). The manual scans stay in the owner's Downloads folder. Reason: the repository may become public.

## First observation of the unit #usb #hardware

The scanner enumerates on the Pi 3 as Genesys Logic `05e3:0103` "USB2.0 Scanner", bcdDevice 7.02, and disconnected after 4 min 55 s with nothing talking to it. Details in `doc/hardware/usb.md`. Whether this ID is normal for the model is the first research question.

## Test host power problem #pi #power

The Pi 3 reports continuous undervoltage. Recorded in `SUGGESTIONS.md`. USB faults seen on this host are suspect until the supply is fixed.

## Descriptor watcher on the Pi #tools

`tools/pi/watch-scanner.sh` polls `lsusb` once a second and dumps descriptors on every connect, so the next power-on is captured without anyone having to time it. Polling instead of a udev rule: no system configuration change on the Pi.

## The unit has lost its Plustek USB identity #usb #diagnosis #gl128

Research (`doc/research.md`) found that a working OpticFilm 120 enumerates as `07b3:1406` with bcdDevice `0x0702` (Genesys GL128). The owner's unit has the same bcdDevice but Genesys default VID/PID and strings. The Windows driver matches only `07b3:1406`, which explains "not found" on Windows. Working diagnosis: the scanner's identity configuration is lost or unreadable; whether the rest of the hardware works is untested.

Decision: two tracks.
1. Linux driver: a libusb driver can match `05e3:0103` directly, so the identity does not block it. Base it on the existing GL128 work (pyopticfilm, SANE `gl128.cpp`) plus the OpticFilm 120 capture from SANE issue #151.
2. Identity: find where the GL128 board keeps VID/PID/strings. Restoring it would bring back the vendor software on Windows and macOS. Any write to the scanner's non-volatile storage needs the owner's explicit approval first.

## Standby timer measured #standby

Second run: enumerated 20:38:26, left the bus 20:43:20 (4 min 54 s), first run 4 min 55 s. Recorded in `doc/hardware/usb.md`.

## Unit history from the owner #history #diagnosis

Bought new, worked, then sat unused for several years; on the next use it no longer worked on Windows or macOS. The owner suspects a failed automatic firmware update. A second candidate is loss of the stored data over the idle years. Neither is verified. Plustek's scanner engine contains firmware upgrade and flash programming routines (`doc/vendor-driver/windows.md`), so whether the vendor software ever updates the OpticFilm 120's firmware is now a research question.

## Driver lives in a pyopticfilm fork #design #pyopticfilm

The owner chose to fork pyopticfilm (`Tubbles/pyopticfilm`) and include it as the `pyopticfilm/` submodule, instead of writing a separate driver here. Rationale and consequences in `DESIGN.md`. The submodule URL is HTTPS so anyone can clone; pushes use SSH (`remote.origin.pushurl`).

## Hardware budget #hardware #flash

The owner is open to buying modest hardware (for example an SPI flash clip or a logic analyser) and to desoldering parts as a very last resort. Order of preference: read the flash through the ASIC over USB first (free, non-invasive), then board photos, then external tools.
