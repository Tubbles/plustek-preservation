# 0016 SilverFast Ai Studio 8 on Linux

Status: todo (research 2026-10-15, first steps need the owner's input)

Owner's goal (2026-10-15): SilverFast Ai Studio 8, the front end bundled with the OpticFilm 120 (`doc/manual/quick-guide.md`: the DVD's `InstallPilot.exe`, SilverFast 8.0.0r1, unlocked on first start with name and serial; the serial is in `work/sensitive.md`), working on Linux, through Wine, a port, or other means.

## What is known

- LaserSoft ships SilverFast for Windows and macOS only. The [model page](https://www.silverfast.com/models/plustek-opticfilm-120/) lists SilverFast 9 for Windows 7 to 11 (64-bit) and macOS 10.13 to 27, and SilverFast 8 as "Support for Legacy Systems" for Windows XP to 10 and macOS 10.5 to 12. The [activation page](https://www.silverfast.com/show/activation-plustek/en.html) offers those systems only, asks for the scanner model, the operating system and the scanner's serial number, and says a SilverFast 8.8 serial upgrades to 9 free and that registered users reinstall through the MySilverFast portal. No Linux build exists, and the program is closed source, so a port is not a route.
- Nobody has reported SilverFast 8 under Wine: no entry turned up in the Wine AppDB, [CodeWeavers lists "SilverFast 8 Ai"](https://www.codeweavers.com/compatibility/crossover/silverfast-8-ai) as unrated, never tested and "manual install", and a [2009 WineHQ bug](https://www.winehq.org/pipermail/wine-bugs/2009-June/183014.html) on an older SilverFast was closed without details. Plustek's installer registers SilverFast's uninstall key `SilverFast UScan_is1` and the launcher `SF Launcher.exe` (`work/re-win/registry-V5020.txt`, key `A31\USB`); the `_is1` suffix is Inno Setup's, so the SilverFast installer is an Inno Setup one *(inference)*, a kind that installs under Wine as a rule.
- On Windows the scanner is reached as application, then `Scanapi.dll` (Plustek's engine in user space, the 43-slot function table of `SCANAPI_GetFunctionTable`), then `DeviceIoControl` on Microsoft's kernel driver `usbscan.sys`, which Plustek's INF binds to `USB\VID_07B3&PID_1406` (`doc/vendor-driver/windows.md`, "Layers" and "Transport"): six IOCTLs for the control transfers, the descriptors and the interrupt pipe, and the bulk pipes through the same file handle *(inference: usbscan maps reads and writes to the bulk pipes)*. Whether SilverFast calls the function table itself or goes through WIA is not checked (`windows.md`, open question 4). On macOS SilverFast loads Plustek's `ScanApi` framework from its own `Drivers/Plustek/` folder, in user space (`doc/vendor-driver/macos.md`, "Layout"), so the direct route is the one Plustek built for it *(inference)*.
- Identity: every vendor stack matches `07b3:1406` only, and the owner's unit says `05e3:0103` (`doc/hardware/usb.md`). The engine itself would open the unit with a registry subkey `Vid_05e3&Pid_0103` holding the A31 values or an ini file `ScanApi_05e3_0103.ini` next to it, once `usbscan.sys` is bound to the unit by a modified INF (`windows.md`, "Device discovery and configuration", not tried). The engine reads VID and PID from `IOCTL_GET_DEVICE_DESCRIPTOR` and nothing else, so a usbscan replacement that answers with `07b3:1406` would make every vendor component see a healthy unit *(inference)*. What SilverFast checks on its own is unknown.
- Licence: the engine's `apiGetDeviceSerialNumber` returns the USB serial string (`windows.md`, "Device discovery"), and the OpticFilm 120 has none (`macos.md`, "Which configuration file"), so SilverFast cannot read a serial from any OpticFilm 120 *(inference)*. What SilverFast 8 checks at unlock beyond the entered serial is unknown.
- Hosts: `vaio` has Ubuntu 24.04 x86_64, 4 logical CPUs, 7.8 GB RAM, 54 GB free, KVM, qemu-system-x86 8.2.2, the usbip tools and wine 9.0 with `wine64` only (no `wine32`, no `winegcc`, no mingw; checked 2026-10-15). Wine 9.0 ships `wineusb.sys` with its Unix side, the libusb-backed USB bus driver ([wineusb.c at wine-9.0](https://raw.githubusercontent.com/wine-mirror/wine/wine-9.0/dlls/wineusb.sys/wineusb.c)): it enumerates every USB device as a PDO with hardware ID `USB\VID_%04X&PID_%04X&REV_%04X` and answers URBs for vendor control transfers, bulk and interrupt transfers, descriptor reads, configuration select, abort and reset pipe. Wine's PnP manager ([pnp.c](https://raw.githubusercontent.com/wine-mirror/wine/wine-9.0/dlls/ntoskrnl.exe/pnp.c)) installs a driver for a new PDO through setupapi's INF matching on the hardware ID and loads the named service with `ZwLoadDriver`, native drivers included, and implements `IoRegisterDeviceInterface` and `IoSetDeviceInterfaceState`, which is what the engine's `SetupDiGetClassDevs(GUID_DEVINTERFACE_IMAGE)` discovery needs. The scanner hangs on the Pi (aarch64, no x86 emulation), so Wine or a Windows guest runs on `vaio` with the scanner cabled to it or forwarded with USB/IP (the Pi side needs the `usbip` package and its kernel module, a system install for the owner to approve).
- The Plustek V5 packages carry one `USBSCAN.SYS` (same hash in V5.0.0.2 to V5.0.1.0, folders `DRVUSB_kernel` and `DRVUSB_kerne_98`): a 32-bit driver linked on 1998-04-29, importing 28 ntoskrnl functions and 2 usbd ones, all of which Wine 9's `ntoskrnl.exe` and `usbd.sys` export (checked 2026-10-15 with `objdump -p`, lists in `tmp/`). It creates `\\.\UsbscanN` names with `IoCreateSymbolicLink` and registers no device interface, which only the engine's pre-Windows-2000 discovery path uses, and a 32-bit kernel driver needs a 32-bit prefix. So the Wine route with Microsoft's driver needs the 64-bit `usbscan.sys` of a Windows 7 or later installation, whose imports are not checked.

## Options

1. A Windows guest on `vaio` (KVM, QEMU `usb-host` passthrough of `05e3:0103`) with Plustek's driver and SilverFast 8 unchanged. Needs from the owner: a Windows licence and installation image (Windows 7 accepts the unsigned INF with a warning, as the Quick Guide describes; Windows 10 needs driver signature enforcement off for a modified INF), and the SilverFast 8 installer. Needs from this side: the INF modified to bind `USB\VID_05E3&PID_0103`, the registry subkey or ini file for the identity. Value: the most certain way to a SilverFast scan, and the host's `usbmon` records the vendor stack scanning the owner's own unit, which is phase 3 of `PLAN.md`. Risk: the identity bridge is untested, SilverFast's own checks are unknown, and a guest on a dual-core laptop with 7.8 GB is slow but workable *(inference)*.
2. Wine on `vaio` with the vendor stack: SilverFast 8 and `Scanapi.dll` as native Win32 code, the engine's registry values imported from `work/re-win/registry-V5020.txt`, and a `usbscan.sys` on top of `wineusb.sys`. Two variants: (a) Microsoft's 64-bit `usbscan.sys` loaded by Wine's kernel through an INF for `05e3:0103` (zero new code if its imports exist in Wine; the Plustek packages ship only the 32-bit Windows 98 driver, see above); (b) a small open `usbscan.sys` written for Wine, built with mingw-w64 (a system install), implementing the six IOCTLs, the bulk reads and writes and the image device interface on URBs to the wineusb PDO, with the descriptor answer rewritten to `07b3:1406`. Value: everything on Linux, no Windows licence, and (b) is reusable for every usbscan-based scanner under Wine. Risk: whether SilverFast 8 installs and runs in Wine at all is untested by anyone; a 32-bit SilverFast or installer needs `wine32` (a system install); if SilverFast goes through WIA instead of the function table, Wine's WIA service is a further gap *(not checked)*; libusb access to the device needs a udev rule.
3. A replacement `Scanapi.dll` for Wine on top of pyopticfilm (over a socket to the Pi, or in process on `vaio`): SilverFast becomes a front end of the open driver, with no vendor engine and no identity problem. The API is the 43-slot table (`engine/macos/Sources/Api.cpp` is the reconstructed reference, private, so the replacement is a clean-room implementation from the documented API, not a copy). Possible only once pyopticfilm scans (`0015-pyopticfilm-opticfilm-120.md`, then the scan item), and option 2's first question (SilverFast under Wine at all) applies. The long-term route.
